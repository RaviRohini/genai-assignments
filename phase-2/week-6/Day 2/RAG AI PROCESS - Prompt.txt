# ICESPOT Prompt: RAG AI PROCESS Enhancement

## I — Instruction

Enhance the existing Resume RAG application by introducing a new **“RAG AI PROCESS”** stage between the existing **Search Mode** and **Results Limit** sections.

The new RAG AI PROCESS should automatically process the resumes retrieved from the selected search mode and perform:

1. **Re-ranking** of retrieved resumes.
2. **Deduplication** of repeated resumes.
3. **Summarization** of the final relevant results.
4. Complete end-to-end integration from search → RAG AI PROCESS → final results.

Do not rebuild or replace existing working functionality. First inspect the current implementation and integrate the new functionality into the existing architecture.

---

# C — Context

The application already supports different resume retrieval modes:

* **Vector Search**
* **BM25 Keyword Search**
* **Hybrid Search**

The selected search mode determines how resumes are initially retrieved.

The enhanced workflow should be:

```text
User enters search query
        ↓
Select Search Mode
(Vector / BM25 / Hybrid)
        ↓
Retrieve Resumes
        ↓
RAG AI PROCESS
        ↓
Re-ranking
        ↓
Deduplication
        ↓
Final Result Selection
        ↓
Summarization
        ↓
Display Final Results
```

The **RAG AI PROCESS** should automatically start after resume retrieval. The user should not need to manually trigger each RAG operation.

## 2. Re-ranking

Implement a re-ranking stage that evaluates the retrieved resumes against the user's search query.

Requirements:

* Re-rank retrieved resumes based on relevance.
* Preserve relevant resume metadata.
* Display the final ranking clearly.
* Higher relevance should appear first.
* Avoid inventing candidate information.

Re-ranking Score Display

Display it directly on each resume card:

┌─────────────────────────────────────────┐
│ #1  Candidate Name                      │
│                                         │
│ Re-ranking Score: 94%                   │
│ ███████████████████░                    │
│                                         │
│ Skills: Java, Selenium, API Testing     │
│ Experience: 4+ Years                    │
└─────────────────────────────────────────┘
Recommended interpretation
Score	Meaning
90–100%	Highly relevant
75–89%	Very relevant
60–74%	Relevant
40–59%	Partially relevant
0–39%	Low relevance
Important implementation rule

The score should be calculated from the actual re-ranking process, not hardcoded.

For example:

Initial Retrieval
      ↓
20 resumes retrieved
      ↓
Deduplication
      ↓
15 unique resumes
      ↓
Re-ranking
      ↓
Resume A → 94%
Resume B → 89%
Resume C → 82%
...
      ↓
Final Results

The UI can show:

Re-ranking: 15 resumes evaluated → Top 10 selected

and each resume can show:

Re-ranking Score: 94%

Add this to your ICESPOT prompt

Re-ranking Score Display: Calculate a normalized re-ranking relevance score between 0 and 100 for every final resume based on its relevance to the user's search query. Display the score prominently on each resume result card as a percentage. Sort the final results in descending order of the re-ranking score. The score must be dynamically calculated from the actual re-ranking process and must not be hardcoded. Also display a processing summary showing how many resumes were evaluated, how many were re-ranked, and how many were selected for the final results.

Example:

```text
Original Results: 20

After Re-ranking:
1. Candidate A — 95%
2. Candidate B — 91%
3. Candidate C — 87%
```

The actual scoring mechanism should reuse the existing RAG/retrieval architecture where possible.

## 3. Deduplication

Remove duplicate resumes before displaying the final results.

Duplicates may occur when:

* Vector Search returns the same resume multiple times.
* BM25 returns overlapping results.
* Hybrid Search combines results from multiple retrieval methods.

Use a reliable unique identifier such as:

* Resume ID
* MongoDB document ID
* Source file identifier
* Resume hash

The final UI must not display the same resume more than once.

---

## 4. Summarization

After re-ranking and deduplication, generate a concise summary of the final relevant resumes.

The summary should:

* Be based only on retrieved resume information.
* Highlight relevant skills and experience.
* Explain the overall relevance of the results.
* Avoid hallucinating candidate information.
* Clearly separate summary information from individual resume data.

Example:

```text
RAG AI Summary

5 relevant resumes were identified.

Most candidates have strong experience in
Java, Selenium and API testing. The top-ranked
candidates have relevant automation testing
experience and closely match the search criteria.
```
